# 高德数据源实测结论（AmapProvider 实现规格）

> 本文所有数字均为**实测值**，不是文档推断。验证时间见脚本输出。
> 验证脚本：[verify-amap-key.sh](../tools/verify-amap-key.sh)
> 验证范围：`v3/geocode/geo`、`v3/direction/driving`、`v5/direction/driving`

---

## 1. 一句话结论

**用 v3 驾车路径规划，从 `polyline` 自算 bearing，用 `road` 做文案，忽略 `orientation`。**

---

## 2. 实测字段清单

### 2.1 v3 `direction/driving` 返回结构

```
顶层:      count, info, infocode, route, status
route.paths[0]:  distance, duration, restriction, steps, strategy,
                 toll_distance, tolls, traffic_lights
step:      action, assistant_action, cities, distance, duration, instruction,
           orientation, polyline, tmcs, toll_distance, toll_road, tolls
```

### 2.2 v5 `direction/driving` 返回结构

```
step:      cost, instruction, orientation, polyline, step_distance, tmcs
```

> ⚠️ **v5 的 step 不带 `road` 字段**（需要 `show_fields` 指定或根本不给）。
> **本项目选 v3** —— `road` 开箱可用，而 `road` 是我们生成高风险清单文案的必需品。

---

## 3. 三个字段的实测结论

### 3.1 `orientation` —— ❌ 不可用于计算

**实测取值**（唯一值全枚举）：`东 东北 东南 北 南 西 西北 西南` —— **共 8 档，45° 分辨率**。

这个字段有**两个独立的致命问题**：

| 问题 | 实测证据 |
| --- | --- |
| **① 分辨率太粗** | 只有 8 档。而我们的 `w_angle` 在 θ=15° 处权重已降到 0.5 —— **量化误差（±22.5°）比信号本身还大** |
| **② 每个 step 只给一个值** | G2京沪高速 有一段的 `distance = 97776m`（97.7 公里），**只配一个「东南」**。G3京台高速 有一段 49371m 只配一个「南」 |

**量化验证**（北京→济南 406km，28 个 step）：把 `orientation` 与「该 step 首尾连线方位角」对比，

- 平均偏差 **8.1°**，最大 **26.8°**（崔寨南立交，`orientation=西`，实际首尾方位 247°）
- 偏差分布与「8 档量化的理论最大误差 22.5°」一致 → 确认它就是量化方位

**还有一个更隐蔽的坑**：我曾假设 `orientation` 是「方位角量化」，于是想拿它当折线自算 bearing 的**校准基准**。但实测发现折线逐段 bearing 与 step 级 `orientation` 有 **约 30% 不一致**。

这个 30% 说明：**`orientation` 不是「方位角」，而是导航播报语义下的「道路走向描述」**。它和瞬时航向是**不同的量**。所以它连做 sanity check 的资格都没有 —— 拿它校准会把正确的计算结果「校准」错。

> **结论**：`orientation` 只能作为 UI 上的粗略文字提示（如「该段向东行驶」），**不得进入任何计算**。

### 3.2 `road` —— ✅ 直接可用

实测取值样例：

```
东华门路、东华门大街、南池子大街、东长安街、建国门外大街、国贸桥、
分钟寺桥、G2京沪高速、徐庄子匝道桥、崇文门内大街、榴乡路、
G3京台高速、G3京台高速出口、二环东高架路、崔寨南立交、奥体西路
```

**质量评估**：高速编号（`G2京沪高速`）、立交桥（`崔寨南立交`）、匝道（`徐庄子匝道桥`）都能正确识别。

**用途**：直接喂给 PRD 第 F5 节的高风险清单文案，例如：

> **G2京沪高速**（K120–K145 段）｜约 07:20–08:05 正对太阳｜**高**｜建议佩戴偏光墨镜

**注意**：部分 step 的 `road` 为空字符串或 `null`（实测 step[0] 就是这种情况）。UI 需要 fallback 文案，如「未命名路段」或用 `instruction` 字段。

### 3.3 `polyline` —— ✅ 这是 bearing 的权威来源

**格式**：`lon,lat;lon,lat;...` 分号分隔的坐标串。

**实测密度**（北京→济南 406km）：

| 指标 | 值 |
| --- | --- |
| 折线点总数 | 3315 |
| 折线段数 | 3314 |
| 段间距 P25 | 52.2 m |
| **段间距中位** | **96.6 m** |
| 段间距 P75 | 148.1 m |
| 段间距最大 | 1242.4 m |
| ≤100m 的段占比 | 52.4% |

**这条数据非常关键**：折线中位间距 **96.6m**，几乎正好命中 PRD 第 6.4 节规划的 **100m 分段粒度**。

> **结论**：**不需要重采样**，折线天然就是我们要的分段。这省掉了一整个处理步骤。

**间距注意**：最大 1242m、最小 0.0m（重复点）。实现时必须：
- 丢弃间距 < 1m 的退化段（否则 bearing 计算会出现 NaN 或抖动）
- 对间距 > 300m 的长段做插值细分（否则该段的朝向代表性不足）

## 4. 两个数值验证

### 4.1 GCJ-02 坐标系对 bearing 的影响 —— 可忽略（0.25°）

高德返回的坐标是 **GCJ-02**（火星坐标），不是 WGS-84。这引出一个必须回答的问题：**用 GCJ-02 坐标算 bearing，会不会被坐标偏移污染？**

**实测**：取真实高速路段（分钟寺桥，7516m，89 个折线点），把每个折线点做 GCJ-02 → WGS-84 逆向变换后重新计算 bearing，对比：

```
同一路段在两种坐标系下算出的 bearing 最大差异: 0.2513°
```

**为什么这么小** —— 原因值得记下来：

> GCJ-02 的偏移量在**局部近似是常数**。计算 bearing 时做的是**两点求差**，常数偏移量在相减时**被消掉了**，只剩极小的梯度项。

所以：
- **bearing 计算可以放心用 GCJ-02 坐标**，误差 0.25° 远小于我们 5° 的分级粒度
- 不需要为了算方位而做坐标转换

### 4.2 但**位置**偏移 710m —— 必须处理

```
实测天安门 GCJ-02 偏移: 710m 量级
```

**这必须处理**，否则路线会飘在底图外面。规则：

| 用途 | 是否需要转换 |
| --- | --- |
| 算 bearing（两点求差） | ❌ 不需要 |
| 算太阳位置（用 lat/lon） | ❌ 不需要（710m ≈ 太阳正午时刻 2 秒误差，可忽略） |
| **地图上画线** | ✅ **必须与底图坐标系一致** |
| 算距离 | ⚠️ 用高德返回的 `distance` 字段，别自己从坐标算 |

**实现规则**：
- **若底图用高德瓦片（GCJ-02）** → 全链路保持 GCJ-02，零转换。**推荐**。
- **若底图用 OSM 瓦片（WGS-84）** → 必须把 GCJ-02 转成 WGS-84，或在双 Provider 架构里统一坐标系。

这正好印证 PRD 第 3.2 节的约束 **C4**。

## 5. 性能推算

基于实测的 3314 段（406km）：

```
406km 路线  = 3314 段
每段 6 小时行程 / 5 分钟采样 = 72 个时间点
总计        = 238,608 次太阳位置计算
```

**对比 PRD 第 5 节的非功能要求**（300km ≤ 8 秒）：

- 300km 约 2450 段 × 72 ≈ **176,000 次**计算
- 太阳位置算法（NOAA SPA 级）单次约 1–3 μs，纯计算约 **0.2–0.5 秒**
- **结论：性能要求可达，无需 Web Worker 也能过**
- 但仍建议放 Worker，避免阻塞 UI 渲染；且「建议出发时间」要跑 24 次，累计约 5 秒，正好卡在 PRD F6 的 5 秒预算上

## 6. Provider 实现要点清单

从上述实测推导出的实现规范：

| # | 要求 | 原因（实测依据） |
| --- | --- | --- |
| 1 | 用 **v3** 接口，不用 v5 | v5 step 无 `road` 字段 |
| 2 | bearing **从 `polyline` 自算**（大圆方位角公式） | `orientation` 只有 8 档且每 step 一个值 |
| 3 | **不要**用 `orientation` 当校准基准 | 它是「道路走向描述」，与瞬时航向语义不同（30% 不一致） |
| 4 | `road` 为空时提供 fallback 文案 | 实测 step[0] 的 `road` 为 null |
| 5 | 丢弃间距 < 1m 的退化段 | 实测存在 0.0m 段 |
| 6 | 对间距 > 300m 的段做插值细分 | 实测最大间距 1242m |
| 7 | 距离用返回的 `distance` 字段 | 避免坐标系引入的距离误差 |
| 8 | 时间用返回的 `duration` 字段推算 | 同上，且含路况估计 |
| 9 | 全链路统一 GCJ-02（若用高德底图） | 位置偏移 710m |
| 10 | 必须配置 `extensions=all` | 否则拿不到完整 `steps` 和 `tmcs` |
