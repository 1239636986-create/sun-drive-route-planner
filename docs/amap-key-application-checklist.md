## 2. 关键决策：个人认证还是企业认证

这不是「额度大小」的选择，而是**用途合法性**的选择。高德官方公告原文：

> 我们在此提醒您，**若您并非是为了个人目的而使用高德开放平台产品和服务，请您务必选择"企业开发者"进行认证**，以避免导致您个人对企业行为承担责任。

对照你的实际情况选：

| 你的目的 | 认证类型 | 说明 |
| --- | --- | --- |
| 自己开发、自己开车用、验证算法 | **个人认证** ✅ | 本项目的当前阶段，就是这一档 |
| 给朋友/公众使用、要上线、要商业化 | **企业认证** | 个人认证跑商用，风险落到你个人身上 |

> **本项目的建议**：现在选**个人认证**。理由是当前目标是「让算法跑在真实中国路网上」，不是发布产品。等算法验证完、确认这东西真有用，再决定要不要走企业认证。这样认证和 Key **都不在关键路径上**，今天就能开始做 M0。

## 3. 申请步骤

### 步骤 1：注册开发者账号

打开 <https://console.amap.com/dev/id> → 注册 → 手机号 + 验证码 + 设置密码。

### 步骤 2：完成实名认证 ⚠️ 不做这步，后面建不了 Key

进入 <https://console.amap.com/dev/user/permission>，按自身情况选择**个人**或**企业**身份认证。

> ⚠️ **硬门槛**：自 2021-08-05 起，**未完成实名认证的个人开发者无法新增 Key**，且已删除的应用和 Key 无法恢复。这一步不能跳。

### 步骤 3：创建应用

进入 <https://console.amap.com/dev/key/app> → 创建新应用 → 填应用名称（如 `SunGlare`）。
服务平台按需勾选（下面步骤 4 里说明该选哪个）。

### 步骤 4：添加 Key —— 选对「服务平台」

**这一步最容易选错，而且选错了没法改，只能删了重建。** 本产品需要**两个 Key**：

| Key 序号 | 服务平台该选 | 用途 | 会被谁看到 |
| --- | --- | --- | --- |
| **Key ①** | **Web端 (JS API)** | 在浏览器里显示地图 + 前端直接做驾车路线规划 | 前端公开（有安全密钥+域名白名单兜底）|
| **Key ②**（可选） | **Web服务** | 服务端调用 REST 接口；**我这边可以立刻验证** | 仅服务端，**绝对不能进前端** |

> **建议两个都建。** Key ① 是产品真正要用的；Key ② 本身几乎不耗配额，但它能让我在**几分钟内**验证你的账号权限、配额、以及路径规划返回的字段结构，省掉你手工测试的麻烦。

### 步骤 5：拿到 Key 和**安全密钥**

创建成功后，控制台会同时给出 **Key** 和 **安全密钥 (securityJsCode)**。

> ⚠️ **必须成对使用**：官方明确说明 —— **2021-12-02 之后创建的 Key 必须配备安全密钥一起使用**。
> 本产品若用 JS API，**两个都要拿**，少一个地图加载不出来。

### 步骤 6：设置域名白名单（可选但建议）

在 Key 详情里配置允许的域名。本地开发可先用 `localhost`。

---

## 4. 两个 Key 的硬性使用规则

| | Key ① JS API | Key ② Web 服务 |
| --- | --- | --- |
| 放哪 | 前端，明文 | **只放服务端** |
| 泄漏后果 | 中等（有白名单和安全密钥兜底）| 高 —— 等于把配额送人 |
| 能否放前端 | ✅ 可以（必须配安全密钥）| ❌ **绝对不可以** |

**对本项目架构的影响**：因为我们做的是纯前端 Web，**应该优先走 Key ① JS API 这条路**，这样能保持零后端。

如果将来需要 Key ②，就必须加一层后端代理 —— 那时产品就从「纯静态页面」变成「需要部署服务」。

## 5. 申请完之后

### 方式 A：把「Web服务」Key 给我，我立刻验证

**最快路径。** 我会验证三件事：

1. Key 是否有效、配额是否正常
2. 驾车路径规划**能否返回每段的方向角（orientation）** ← 这决定算法要不要自己从折线推算
3. 真实路线的折线精度如何、道路名是否可用

> 🔒 **安全提示**：Web 服务 Key 是敏感凭据。你可以先在控制台把它的**配额调到最低**、或验证完立即删除重建。我只会用它发几个只读请求，不会写入任何地方（但如果这个工作区将来要提交到 Git，别把 Key 提交进去 —— 我会把它放进 `.env` 并加 `.gitignore`）。

### 方式 B：把「JS API」Key + 安全密钥给我

我会写好前端的加载代码（含安全密钥配置），你打开本地页面就能看到地图和路线。

### 方式 C：先不给 Key

我用 OSM/OSRM 直接把 M0 算法跑通 —— **算法层不关心路网数据来自哪**，这正是 PRD 7.2 双层 Provider 架构的价值。Key 到手后再切数据源，算法代码一行不用改。

## 6. 常见坑（提前避掉）

| # | 坑 | 后果 | 避法 |
| --- | --- | --- | --- |
| 1 | 没实名认证就创建 Key | 创建失败，且反复找不到原因 | 先做步骤 2 |
| 2 | 服务平台选错（把 JS API 选成 Web服务） | Key 用不了，**不能改只能重建** | 步骤 4 的表照着选 |
| 3 | 只用 Key 没配安全密钥 | `INVALID_USER_SCODE`，地图白屏 | 两个都要，按官方 [JS API 安全密钥使用](https://developer.amap.com/api/javascript-api-v2/guide/abc/jscode) 配置 |
| 4 | Web服务 Key 写到前端 | Key 被盗刷，配额秒空 | 走后端代理，或改用 JS API |
| 5 | 个人认证用于商用 | 个人承担企业责任 | 上线前先转企业认证 |
| 6 | Key 提交进了 Git | 泄漏 | 放 `.env` + `.gitignore` |
| 7 | 以为百度能无缝替代 | 百度对个人开发者的限制与高德不同，**需要单独查** | 别默认可以平移 |
