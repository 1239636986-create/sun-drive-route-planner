# 逆光路线规划器 SunGlare Route Planner

出行前预演整条路线的**阳光迎面照射风险**：输入起终点和期望到达时段，告诉你哪几段会正对太阳、什么时候、以及怎么避开。

传统导航回答「怎么走最快」，这个项目回答「**哪一段太阳会糊你一脸**」。

## 核心概念

### 离轴角 θ —— 本产品的核心量

**太阳方向与车头方向的夹角**，不是「太阳方位角与道路方位角的差」。

```
cos θ = cos(太阳高度角) × cos(方位角差)
```

| θ | 含义 |
| --- | --- |
| 0° | 太阳正对车头，最刺眼 |
| 90° | 太阳在正侧方，基本不影响 |
| 180° | 太阳在正后方，完全无影响 |

为什么要用三维夹角而不是方位角差：太阳高挂时即使方位对齐，光也是从上方来的，**遮阳板可以挡**。只有太阳贴近地平线且正对车头时才是真正的危险。

### 风险分数

```
R = 100 × w(θ) × f_sun(h) × f_weather × f_shade × f_terrain
```

**各因子职责严格分离，同一个物理量不得进入两个因子：**

| 因子 | 管什么 | MVP |
| --- | --- | --- |
| `w(θ)` | 几何方向 | ✅ 实现 |
| `f_sun(h)` | 大气衰减（低空太阳散射更强） | ✅ 实现 |
| `f_weather` | 云层遮蔽 | 参数就绪，未接天气 API |
| `f_shade` | 地物遮挡 | 恒为 1（不做遮挡建模） |
| `f_terrain` | 坡度 | 恒为 1（无高程数据） |

分级：`[0,30) 低` / `[30,60) 中` / `[60,80) 高` / `[80,100] 极高`

## 三个必须知道的设计约束

这三条都是**真实数据盲测中踩出来的**，不是理论推导。详见 [M0 验证报告](docs/m0-algorithm-validation-report.md)。

### ① `orientation` 字段不可用

高德返回的 `orientation` 只有 **8 档（45° 分辨率）**，且**每个 step 只给一个值** —— 实测 G2京沪高速 有一段 97,776 米只配一个「东南」。

我们的角度权重在 θ=15° 处已降到 0.5，而量化误差是 ±22.5°。**误差比信号还大。**

→ 必须从 `polyline` 自算 bearing。`orientation` 只能当 UI 上的粗略文字描述。

### ② 不能用「平均暴露度」评价方案优劣

平均类指标系统性**低估「局部致命」**。实测：某路线 85% 东西向，但致命的只有 3.1km 西向路段，平均值把致命点 ÷ 138km 稀释掉，导致优化器推荐「19:00 出发」（太阳已落山）。

→ 主指标用**峰值风险**，并强制输出**峰值下界**。

### ③ 风险曲线不连续，搜索必须两阶段

峰值风险不是出发时间的平滑函数：

```
15:45 -> 100.0   15:50 -> 91.0   16:00 -> 99.5   16:05 -> 23.2   ← 跳变 76 分
```

15 分钟单步长会漏掉 15:00–17:30 内 15 个高危时刻中的 13 个。

→ 两阶段：15 分钟粗扫 + 5 分钟精扫（含所有等级跃迁边界）。

## 数据来源与坐标系

**当前用高德 Web 服务 API（v3 驾车路径规划）。**

| 事项 | 结论 |
| --- | --- |
| 坐标系 | **GCJ-02**。全链路不做转换 |
| 为什么可以不转 | GCJ-02 偏移对 bearing 影响仅 **0.25°**（求差时常数项被消掉） |
| 但位置偏移 | **710m**。所以地图渲染必须与底图坐标系一致 —— 用高德底图则零转换 |
| 距离/时长 | 用接口返回的 `distance` / `duration`，不自行从坐标累加 |
| 折线密度 | 中位间距 **96.6m**，已接近 100m 目标粒度，**不做无谓重采样** |

## API 架构（Q8 已定稿）

**反向代理 + 服务端注入凭据。客户端零密钥。**

```
┌──────────┐  /amap-api/v3/direction/driving?origin=...&destination=...
│  浏览器   │ ────────────────────────────────────────┐
└──────────┘   无 key，无 jscode                       │
                                                        ▼
                              ┌────────────────────────────────┐
                              │ 反向代理                        │
                              │ 开发: Vite dev server          │
                              │ 生产: nginx / serverless        │
                              │ 注入 &key=AMAP_WEB_KEY          │
                              └──────────────┬─────────────────┘
                                             ▼
                                  https://restapi.amap.com
```

**实测验证**：经此路径返回的数据与直连完全一致（138536m / 21 steps / 17 个有 road / `G2京沪高速 97776m`），而浏览器侧零密钥。

**因此不需要**：高德 JS API Key、securityJsCode、域名白名单。
**一个 Web服务 Key 覆盖**：路线规划 + 地理编码 + 地图瓦片。

> ⚠️ 实测踩坑：`jscode` 参数对 REST v3 接口**无效**（返回 `INVALID_USER_KEY / 10001`）。
> 高德官方 Nginx 示例里的 `jscode` 是给 JS API 地图服务用的，路径规划这类 REST 接口要的是 `key`。

完整依据见 [Q8 决策文档](docs/q8-api-architecture-decision.md)。

### 两个 M2 期间修掉的真实缺陷

**① `{s}` 子域占位符未被展开 —— 底图全黑**

MapLibre GL JS **v5 已移除 `subdomains` 字段**（实测 5.24.0，其 `.d.ts` 中完全不含该字段）。
传了会被**静默忽略**，于是 `{s}` 永远不被替换，请求打到
`https://webrd0{s}.is.autonavi.com/...` 这种不存在的域名。

→ 修法：瓦片 URL 直接写死子域（`webrd01` / `webst01`），不依赖 `{s}`。
已加测试守护：**任何瓦片 URL 出现 `{s}` 即失败**。

**② 图层注册在 `map.on('load')` —— 底图慢时路线永不显示**

`load` 要等「所有资源加载完 + 首帧渲染完」才触发。实测在软件光栅化环境下它
**从不触发**（`style.load` 与 `render` 都正常），挂在 `load` 里的
`addSource`/`addLayer` 就永远不执行。

这不只是无头环境的问题：**真实浏览器里若瓦片慢或被限流，`load` 同样会长期不触发**，
用户会看到一张没有路线的空地图 —— 而我们的路线是本地数据，根本不该等底图。

→ 修法：改用 `style.load` 并加幂等 guard。

## 部署

前端是纯静态产物，但**必须有一个反向代理注入高德凭据**。

### nginx

```nginx
server {
  listen 80;
  root /path/to/dist;

  location /amap-api/ {
    set $args "$args&key=你的Web服务Key";
    proxy_pass https://restapi.amap.com/;
    proxy_ssl_server_name on;
  }

  location / {
    try_files $uri $uri/ /index.html;
  }
}
```

> 注意是 `key` 而不是官方示例里的 `jscode` —— 后者对 REST v3 接口无效
> （实测返回 `INVALID_USER_KEY / 10001`）。见 [Q8 决策](docs/q8-api-architecture-decision.md)。

### 前端已做的保护

- 启动时调用 `probeProxy()`，代理未就绪会给出**可操作提示**而不是白屏
- 14 条静态测试扫描 `src/`，**禁止密钥出现在前端代码中**

## 已知限制（MVP 阶段）

| # | 限制 | 影响 |
| --- | --- | --- |
| 1 | **不做遮挡建模** | 山体/建筑/树林挡光时仍会报风险。产品定位为「上界估算」，免责声明已说明 |
| 2 | **无高程数据** | 上下坡时太阳相对车头的真实高度角有偏差，山区误差放大 |
| 3 | **天气是单一城市估计** | 取行程中点所在城市的当日预报，未逐段取天气。UI 已标注 |
| 4 | **天气预报仅 4 天** | 高德限制。超出范围的日期天气降级为「未知」，不假装有数据 |
| 5 | **低天气系数下候选项无区分** | 小雨（0.15）把所有风险压到同一档，候选峰值并列。UI 已说明 |
| 6 | **阈值未经实测校准** | `θ₀=15°`、`p=1.6` 为经验值，需真实驾驶反馈调整 |
| 7 | **底图依赖未公开瓦片地址** | 已做可切换注册表（Esri/OSM 备选），失效时切换即可 |
| 8 | **构建产物 1.26MB** | MapLibre 占大头，未做代码分割 |
